# FEM Cloud 웹 UI 프리뷰 — 2026-11-12

## 범위

기존 Next.js 16.1.6 / next-intl / React 프로젝트의 `/ko/fem-ai`, `/en/fem-ai`만 확장한다.
공통 메뉴·푸터·사업자정보·ko/en 라우팅·결제·인증·운영 설정은 유지한다.
FEM/FEM-Automation 소스, FEM 3.2 엔진, 자동화 데몬, 운영 배포는 이번 범위에 포함하지 않는다.

## 지금 제공하는 화면

- Cloud-first 기업용 소개, 단계별 서비스 흐름, 기업 PoC 문의, 후순위 온프레미스 안내.
- 단일 STEP/STP/BREP 로컬 파일 선택·드롭. 확장자, 빈 파일, 100 MiB 상한 검사.
- 내용·형상·내부 단위 검증은 하지 않는다. 확장자가 맞는 손상 파일도 형상 검증 통과로 표시하지 않는다.
- 검토 권한·비기밀 테스트 자료 확인 후 요소 크기, 단위(mm/cm/m), Hex 우선/혼합/Tet,
  1차/2차 요소, 최소 Scaled Jacobian·최대 Aspect Ratio 목표를 로컬에서 검토한다.
- 엔진 미연결·작업 미제출을 명시한다. 메싱 실행, 진행률, 완료 시각, 성공 결과를 만들지 않는다.
- 3D 영역·회전/와이어프레임/화면 맞춤 도구는 빈 상태와 비활성 상태만 제공한다.
  실제 STEP/BREP 파싱, 3D 렌더러, 결과 로더는 미구현이다.
- Hex/Wedge/Tet 수, 최소 Scaled Jacobian, 최대 Aspect Ratio, 품질 미달 요소는 `—`(측정 없음).
- Abaqus INP / Gmsh MSH 버튼은 항상 비활성이다. 샘플 결과물이나 다운로드 링크는 생성하지 않는다.
- 소개 영역의 직접 제작 SVG는 개념도라고 표시하며 업로드 파일·엔진 결과로 사용하지 않는다.
- 기업 문의는 공통 사업자정보의 연락처를 사용하는 mailto 링크다. 자동 발송하거나 CAD를 첨부하지 않는다.

## 데이터 취급

File 객체는 선택 이벤트에서 이름·크기·형식만 추출한다. 파일 내용 읽기, File 장기 보관,
fetch/XHR/FormData, 서버 업로드 API, DB/스토리지 연결, localStorage/IndexedDB, CAD 로그가 없다.
파일 입력값은 선택 직후 비운다. 선택 해제·전체 초기화·새로고침 시 선택 메타데이터가 사라진다.
설정과 동의는 새로고침·전체 초기화 시 해제된다. 언어 전환도 상태 저장을 제공하지 않는다.
공통 사이트의 기존 인증·세션 처리는 그대로 유지되며 CAD 데이터와 연결하지 않는다.

암호화·기업별 접근 제어·처리 리전·보관/삭제 기간·백업 삭제 범위는 **클라우드 활성화 전 확정할 요건**으로만 표시한다.
고객 CAD 학습 이용 기본 비허용 및 별도 명시 동의를 도입 원칙으로 설명한다. 현재 수집 자체가 없다.
기존 개인정보처리방침은 수정하지 않았으며, FEM 업로드 서비스 활성화 전에 계약·업로드 정책과 함께 검토해야 한다.

## 후속 엔진 연결 경계 (이번에는 구현하지 않음)

1. 기업 인증·권한·자료 이용 권한, 업로드 정책 동의 버전, 지역·보관·삭제 정책을 서버에서 검증.
2. 서버 업로드 제한·파일 검사·형상 유효성·단위·엔진 지원 옵션 확인. UI 제한만 신뢰하지 않는다.
3. 웹 전용 작업 API와 엔진 어댑터를 별도 승인된 작업에서 구축. 기존 데몬에 직접 연결하지 않는다.
4. 실제 작업 ID와 서버 상태를 근거로 대기/실행/실패/취소/완료를 표시. 연결 실패를 성공으로 대체하지 않는다.
5. 요소별 품질 지표의 정의·범위·지원 차수를 확정하고 실제 측정값·오류 위치를 표시.
6. 검증된 실제 메쉬 자산을 3D 뷰어에 로드하고, 접근 권한이 있는 실제 INP/MSH 결과만 다운로드.

## 로컬 검증

운영 `.env.local`을 복사하지 않고 추적 파일만 작업 사본으로 복사했다.
로컬 프리뷰에는 서비스 접근이 불가능한 루프백 인증 주소와 플레이스홀더 키만 사용한다.
운영 DB·결제·메일·FEM 엔진을 호출하는 테스트는 하지 않는다.

기존 프로젝트에서 실행:

```sh
npm run dev -- --hostname 127.0.0.1 --port 3100
```

확인 경로: `http://127.0.0.1:3100/ko/fem-ai`, `http://127.0.0.1:3100/en/fem-ai`.
운영 자격 증명을 사용하는 브라우저 세션 대신 프리뷰 전용 환경을 사용한다.

개발 서버를 종료한 다음 빌드와 타입체크를 순차 실행한다:

```sh
node scripts/verify-fem-preflight.mjs
npm run build
npx tsc --noEmit
git diff --check
```

기존 `next/font/google` 때문에 빌드에는 Google Fonts 네트워크 접근이 필요하다.
개발 서버와 빌드를 동시에 실행하면 `.next/dev/types` 생성 파일 경합이 생길 수 있으므로 순차 실행한다.
새 패키지·락파일·운영 환경변수 변경은 없다.

브라우저 확인 절차:

1. 파일 없음/동의 없음에서 설정 진행 버튼이 비활성인지 확인.
2. STL, 빈 STEP, 100 MiB 초과 파일, 복수 드롭을 거부하는지 확인. 유효 파일 다음 오류 파일을 선택해도 이전 선택이 남지 않는지 확인.
3. 비기밀 테스트 STEP/BREP 선택 후 `로컬 선택됨 · 업로드 안 됨` 표시와 형상 미검증 문구 확인.
4. 동의 후 설정 진입. 요소 크기 0, Scaled Jacobian 0/1 초과, Aspect Ratio 1 미만/1,000 초과를 거부하는지 확인.
5. 유효 설정 → 실행 가능 상태 확인. 작업 미제출, 모든 단계 실행 안 됨, 실행 버튼 비활성 확인.
6. 품질 화면에서 7개 지표 모두 `—`, 뷰어 도구와 2개 다운로드 버튼 비활성 확인.
7. 선택 해제·초기화·새로고침 후 파일 정보가 남지 않는지 확인. KR/US 경로 전환과 모바일 레이아웃 확인.

## 배포

로컬 변경과 검증만 수행한다. `git push`, Firebase 롤아웃·배포·운영 테스트는 실행하지 않는다.
운영 배포는 사용자의 별도 승인 후 진행한다. 기존 규칙상 main push가 운영 자동 배포를 유발한다.
